# Откуда растёт autothing

> Собрано 2026-10-10 по открытым материалам компании и реестру РФРИТ. Это контекст о нашей компании и текущих продуктах для тех, кто приходит в проект autothing без этого знания.

## Компания

- Разработчик систем управления освещением и BMS, работает с 2016; входит в промышленную группу, которая производит аппаратную часть ПАК.
- Более 400 объектов. По данным РФРИТ — лидер рынка систем управления внутренним освещением в РФ.
- Член DALI Alliance (DiiA) с 2021.

## Концепция: цифровая тень (Control Shadow), с 2018

Виртуальная 3D-модель объекта как **единая среда управления** всеми инженерными системами: освещение, жалюзи, климат, ОПС, видеонаблюдение. Ключевые тезисы, которые напрямую перешли в autothing:

- Единая информационная база: архитектура объекта, расположение оборудования, адресация, параметры настройки.
- При добавлении нового устройства в тень добавляется **«стандартный элемент с присущими ему свойствами»** — то есть типизированная модель объекта.
- Представление «от всего объекта целиком до каждого устройства» — многоуровневость.
- Копия тени в облаке — защита от утраты проектной документации при смене подрядчика или инженера. Это ответ на вопрос «как объект устроен», когда люди ушли.
- Пользователь без инженера может контролировать и перенастраивать систему.

В PRD для Заказчика 2 (2026, наружное освещение) тень формализована через **устройство / соединение / несущую конструкцию** — см. [`tz/customer2-asuno.md`](tz/customer2-asuno.md).

## Грант РФРИТ на доработку IoT-платформы (2022–2026)

Цель — платформа для замены зарубежных BMS (Schneider, Honeywell, Siemens) на существующих и проектируемых объектах + интеграция с BIM.

- **Этап 1:** Modbus, KNX, DMX512; логика жалюзи, радиаторов, фанкойлов, кондиционеров; API межсервисного взаимодействия; Node-RED; **иерархия проектов и межпроектная навигация** для крупных объектов.
- **Этап 2:** логика вентустановок, термозон, термоконтроллеров; библиотека BIM API; **модуль редактирования и импорта инженерных объектов**, модуль проектной документации, импорт 3D.

«Иерархия проектов» — зародыш территориальной иерархии autothing; «импорт инженерных объектов» — зародыш маппингов.

## Вертикали, где уже есть внедрения

Офисы, отели, склады, производство, школы, птицефермы, уличное освещение (в том числе по энергосервисным контрактам). Финансирование — включая лизинг и энергосервис.

## Что это значит для autothing

Два продукта, одна онтология:

- **Новая платформа** — первый носитель онтологии autothing. Вертикали: уличное освещение, трассы.
- **Действующая BMS** — продукт с внедрениями. Онтология нужна и ей: текущая модель здания расширяется до «от клеммы в шкафу до страны», чтобы здание было узлом той же иерархии, а не отдельным миром.

autothing — не старт с нуля, а следующий шаг: взять модель, проверенную на 400+ объектах, и добавить то, чего в ней нет и что нужно для масштаба региона:

| Есть сейчас | Добавляет autothing |
|---|---|
| Единая модель объектов здания (тень) | Единая модель от страны до клеммы |
| Устройство / соединение / несущая конструкция | + субъекты, владение, договоры |
| История атрибутов, вывод из эксплуатации с датой | Временная валидность всех связей (4D) |
| Иерархия проектов | Федерация узлов edge → регион → центр |
| Один сервер у заказчика | Автономный edge, синхронизация |
| Импорт инженерных объектов | Маппинги к AAS, NGSI-LD, Brick; множественные внешние ID |
| События и отчёты | Наряд как сущность с жизненным циклом |
| Протоколы DALI, Modbus, KNX, DMX, PLC | + BACnet, OPC UA, MQTT/Sparkplug, LwM2M, LoRaWAN, NB-IoT через адаптеры |
