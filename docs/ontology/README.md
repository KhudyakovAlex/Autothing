# Онтология autothing — рабочая область

> Точка входа для любого агента/человека, который продолжает работу над онтологией. Читать после AGENTS.md и [`../concepts/ontology-strategy.md`](../concepts/ontology-strategy.md).
> Синтаксис LinkML и YAML с нуля — [`linkml-intro.md`](linkml-intro.md).

## Зачем

Единая модель объектов для всех вертикалей (BMS, уличное освещение, освещение трасс) и всех уровней иерархии (страна → … → клемма). Собственное ядро, маппинги к внешним стандартам на границах.

## Порядок работы

Онтология строится **сверху вниз от потребностей, а не от классов**:

## Принцип: ядро маленькое и злое

**Маленькое** — минимум категорий, которых хватает описать всё, и ни одной лишней. Два теста на любое понятие:
- нужно только одной вертикали → не в ядро, в вертикальный модуль;
- без него нельзя ответить на вопрос из `questions.md` → обязано быть.

**Злое** — без компромиссов ради удобства момента:
- нет связи без интервала валидности, даже если «здесь оно никогда не меняется»;
- нет атрибута «владелец» / «подрядчик» у объекта — только связь с Субъектом, даже если в проекте он один;
- нет удаления объектов — только вывод из эксплуатации с датой;
- нет «пока захардкодим, потом вынесем» — потом не наступает;
- расширение, не проходящее тест «здание **и** регион», не проходит.

Перед добавлением категории — сначала попробовать выразить через существующие. Добавлять только если не получилось, с записью, какой вопрос без этого не решался.

Противоположность — «большое и доброе»: сорок категорий, под каждый кейс своя, исключения допускаются. Через два года — зоопарк, который нельзя сшить. Это главный риск из AGENTS.md.

## Правила для агентов

- Один файл — одно направление. Не сваливать всё в один документ.
- В шапке каждого файла: статус, дата последнего изменения, открытые вопросы.
- Любое добавление в `core-categories.md` должно быть оправдано хотя бы одним вопросом из `questions.md` или сценарием из `scenarios.md`. Нет оправдания — не добавлять.
- Любое решение проверять: работает для одного здания **и** для региона?
- Не вводить вертикально-специфичные понятия в ядро. Если понятие нужно только освещению трасс — оно живёт в расширении, не здесь.
- Терминология: русские названия в документах, при первом упоминании — английский эквивалент в скобках; английские идентификаторы — в `schema/core.yaml`. Определения понятий модели — в [`../concepts/glossary.md`](../concepts/glossary.md#понятия-модели).
- Категория «Актив» переименована в **«Объект»** (2026-10-10). В `scenarios.md`, `questions.md`, `walkthroughs/`, `research/` слово «актив» пока осталось — читать как «объект»; переименовывать при следующей правке файла, не отдельным проходом.
- Противоречия между файлами фиксировать в разделе «Открытые вопросы» того файла, где они обнаружены, а не молча править соседний.
